3. CORE QUESTION: WHICH SHOULD YOU TRUST MORE?
--------------------------------------------------------------------------------
Question: Which should you trust more:
  (a) the LLM's explanation;
  (b) the independently executed state transitions?

Answer:
  Strictly (b) — The independently executed state transitions.

Engineering Explanation:
1. Nature of the Computation:
   - An LLM generates natural language text autoregressively by predicting the most
     statistically likely next token given previous tokens:
         P(token_t | token_{1:t-1})
     It does not maintain a ground truth register or perform formal logic in its
     inference graph. It is prone to "plausible hallucination"—generating explanations
     that sound completely convincing, fluent, and rigorous, even when an underlying
     precondition has failed.
   - In contrast, the Python/Prolog verification engine computes exact deterministic
     set operations:
         S_{k+1} = (S_k \ NegEff(a_k)) U PosEff(a_k)
     It mathematically cannot output True if a required atom is missing from the set.

2. Verification vs. Rationalization:
   - When asked to justify a flawed plan, an LLM often "rationalizes" why an invalid
     action works (e.g., claiming "the robot moves from A to C" without noticing that
     no edge exists between A and C, or claiming the package is dropped without verifying
     it was picked up).
   - An independent execution engine checks each transition mechanically without bias.

3. The Engineering Takeaway (Handout Page 10 & 11):
   "A generated explanation is not the same as an independent verification."
   In mission-critical autonomous systems, LLMs can be utilized for generative
   synthesis (proposing candidate plans or code), but verification must ALWAYS be
   delegated to an independent, formal logical engine.
