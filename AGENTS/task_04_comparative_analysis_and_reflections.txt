                      |                              | obstacle boundaries          | belief distributions
----------------------+------------------------------+------------------------------+----------------------------------

                      | (e.g. IF obstacle THEN turn) | candidate action sequences   | speed, energy, battery, safety
----------------------+------------------------------+------------------------------+----------------------------------

                      |                              | predicate (is_goal(pos))     | mapping states to real numbers

                      | all rule condition blocks)   | goal coordinates 'G')        | energy, cost, and priority trade-offs)
----------------------+------------------------------+------------------------------+----------------------------------

2. CRITICAL EVALUATION OF THE LLM AS A SOFTWARE ENGINEERING TOOL
--------------------------------------------------------------------------------

Strengths Identified:
1. Rapid Prototyping: Generated a complete, working Python script with grid parsing,
   search logic, and path visualization within seconds.
2. Conceptual Translation: Accurately translated theoretical search concepts (heuristic
   admissibility, Manhattan distance) into idiomatic Python code.
3. Code Clarity: Produced well-commented functions with clear variable names.

Limitations & Vulnerabilities Identified:
1. Monolithic Bias: LLMs tend to write single-file scripts mixing UI, environment physics,
   and agent reasoning unless explicitly prompted for modular object-oriented design.
2. Silent Flaws in Edge Cases: Without strict prompts, an LLM might place the goal check
   inside the expansion loop (breaking A* optimality) or fail to handle disjoint maps.
3. Unverified Claims: An LLM will confidently assert that code is "fully optimal" without
   having run empirical unit tests to verify the claim.

The Fundamental Engineering Lesson:
    "An LLM is an assistant, not an oracle.
     The engineer remains responsible for specification, design, testing, and validation."
